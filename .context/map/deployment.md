# Runtime and deployment
Purpose: Local setup, standalone artifacts, Docker and Caddy host routing.
Entry points: scripts/setup.mjs; scripts/start.mjs; scripts/prepare-standalone.mjs; Dockerfile; compose.yaml; deploy/Caddyfile.docker; deploy/plugin-config.mjs; deploy/plugin-update.sh; scripts/sync-plugin-commands.mjs.
Flow: Build Next standalone output, copy public/static assets and remove bundled .env files. Docker runs the bundled Node runtime; plugin deployment reads/saves host configuration through admin SDK commands and applies it by recreating the app.
Invariants:
- npm start loads .env, resolves DATA_DIR before standalone server.js, and binds BIND_HOST or 127.0.0.1. Docker binds 0.0.0.0, persists /app/data and probes /api/health.
- Docker Compose maps host `${PORT:-3000}` to container port 3000; container PORT is fixed at 3000. Plugin PORT is the host port.
- The deployment plugin performs a one-time recovery from live container environment values that differ from image defaults, then `.env` is authoritative. Protected runtime keys and PORT are excluded from recovery.
- Configuration reads omit known secret values and treat unknown keys as secrets. NODE_ENV, DATA_DIR, BIND_HOST, plugin/socket runtime variables, ERVISIO_VERSION, and Compose/Docker/Buildx keys are protected from edits.
- Configuration commands serialize with `.plugin-config.lock`, stage admin requests in `.plugin-config/requests`, validate a .env revision, back up .env before atomic replacement, and restore the prior .env if Compose rejects it. Applying validates Compose then recreates and health-checks the app.
- Existing Docker image Node runs the shared config helper with networking disabled; host Node.js is not required. The update helper recovers current config before pulling and starting a release.
- Plugin command definitions are generated by `npm run plugin:commands`; plugin build runs `npm run plugin:commands:check` to reject stale manifest commands.
- AUTH_URL is a canonical HTTP(S) origin without path/query/credentials; AUTH_SECRET must be at least 32 characters. AUTH_COOKIE_DOMAIN must match BASE_DOMAIN and include AUTH_URL's hostname; changing AUTH_SECRET invalidates sessions.
- Caddy on-demand TLS asks /api/caddy/ask; security.allowedHost authorizes the canonical host and assigned list subdomains. Compose exposes the app on host loopback; Caddy adds public HTTP/HTTPS and forwards the configured trusted IP header.
- With PLUGIN_SOCKET set, scripts/plugin-socket.mjs sets a per-start PLUGIN_SECRET before Next loads; /api/plugin/* handlers 404 without it. Never store PLUGIN_SECRET in .env.
- Docker socket dir /run/ervisio-todo must be owned by uid 1000 on the host. compose.yaml image is ghcr.io/ervisio/ervisio-todo:${ERVISIO_VERSION}; keep root/plugin versions, manifest/catalog, Compose defaults, .env.example and OpenAPI version aligned for release.
Gotchas:
- DNS for canonical and wildcard hosts is separate from app settings. OAuth callback configuration requires a deployment-specific login check.
- Build uses a placeholder secret; runtime needs its own configuration. Prepare standalone assets after Next builds.
- Caddy, application and upload quotas have separate request size limits. Plugin activity rows use actor NULL because activity.actor is a user FK.
Verification: `npm run typecheck`; `npm test`; `npm run build`; `npm run format:check`; `npm run test:e2e` uses fixture server localhost:3137 and SMTP ports 2527/2528; `npm run test:docker` uses local Caddy CA and ports 3138/3443.
Related: map/storage.md, map/auth-api.md, plugin-contract.md.

- Manifest commands embed static scripts as base64 chunks (<=1024 bytes per argv item, <=64 items); launcher decodes fixed code and forwards validated parameters. Re-run npm run plugin:commands after helper changes.
