# Glass shell (UI)

Purpose: Carry the approved glass shell without repeating the design exploration.
Approved: Variant Studio 005-lists-motion B, 2026-11-09, superseded by the essential shell below (rounds in .variant-studio/rounds, gitignored).
Structure (components/TodoApp.tsx → .glass-shell grid): static backdrop | nav.rail (aria "Progetti": logo = Panoramica, projects, Senza progetto, new project, settings link, account OverflowMenu) | section.slab (aside.lists aria "Navigazione" + main.slab-main: header with title + single "Altre azioni" OverflowMenu, optional search/tag filter, .slab-body, TaskComposer) | .detail-slot (TaskDetailPanel). Mobile: rail + lists slide in together as a drawer, .mobile-bar at the bottom, composer pinned above it, detail as a bottom sheet.
Styles: app/shell.css (imported after globals.css) owns the shell, glass tokens (--glass, --glass-hi, --edge, --hover, --selected), row/menu/detail rules and the few allowed fades. Old sidebar/workspace CSS was pruned from globals.css.
Tooltips: components/ui/TipLayer.tsx (mounted in layout) shows data-tip on hover/focus in a portal, flipping to the side with room; data-tip-side is only the preference. Do not use title= on elements that have data-tip.
Menus: OverflowMenu supports trigger/className/placement (below-end, right-end) and checkbox items (checked → menuitemcheckbox with switch).
Rows (TaskItem): see the essential shell paragraph.
Gotchas: Direct children of .glass-shell get position: relative from `.glass-shell > :not(.shell-fx)`; fixed elements there need `.glass-shell > .x` selectors. A stale .next from `next build` makes `next dev` reload in a loop: rm -rf .next. pkill -f patterns match your own shell; use "[n]ext dev".
Settings area (approved 006-settings-pages A, 2026-11-09): components/shell/SettingsShell.tsx wraps /settings (Aspetto, personal prefs), /account, /settings/workspace (admin form, non-admins redirected) and /api-docs in the glass shell with a sections column (Tu / Spazio di lavoro / Sviluppatori, Esci). SettingsForm takes section="personal"|"workspace". app/settings.css restyles existing form classes under .settings-content. AppHeader was removed; Rail + ShellBackdrop live in components/shell/Rail.tsx and serve both workspace (handlers) and settings (links).
Fonts: self-hosted variable Figtree (--font-sans) and JetBrains Mono (--font-mono, code/kbd/pre) in app/fonts with OFL texts; Manrope removed.
App-wide controls (.button, .field inputs, .switch, .modal-surface) are restyled for glass in shell.css.
Verification (2026-11-09): tsc, next build, unit 55/58 (3 plugin/docker failures pre-exist on main), e2e 4/4, Playwright screenshots desktop/mobile/light/dark.
Update 2026-11-09 (round 2): Settings pages live in route group app/(settings)/ with a shared layout.tsx (SettingsShell persistent, pages render SettingsHead) and loading.tsx; sections: Aspetto, Account, Generali e limiti, Archiviazione, API.
Home (approved 005-home-focus B "Per progetto"): Panoramica (rail logo) opens components/home/HomeView.tsx (today's tasks grouped by project, counts, project and standalone-list chips). TodoApp starts on Home unless opened from /l or /p; a user with no lists or projects still sees the empty state. selectList always sets the project context.
Login/register (approved 003-login-blend A "Minimale con social"): AuthLayout + AuthForm styled by app/auth.css; old .auth-*/.story-* rules removed from globals.css.
Essential shell (approved Variant Studio 008-workspace-essential A, 2026-11-15): clean, few controls, no icon motion.
Structure: static background (no orbs, no entrance animations); rail 56px with icon-only project tiles (logo = Home, "Senza progetto" = tray, plus, settings, account); lists column always open (200px, hairline, project name line, list names only, counts only with showExtras, quiet "Nuova lista"); main = title 26px/650 + one "Altre azioni" menu (Vista: search, Completate, Solo importanti, tag filter, cards, extras | Lista | Progetto, danger last); row = check + title (46px, 50px mobile), star only on hover/focus or when set, one dim word right when due today or overdue (overdue in danger), subtask indicator only with showExtras; composer is a plain row after the last task (pinned on mobile); "N completate" line expands completed rows in place; completing shows a "Completata / Annulla" toast (Toasts.tsx showToast with action).
Detail panel (TaskDetailPanel, 360px glass card): inline editing, no footer; title textarea labelled "Titolo", star, Scadenza pills Oggi/Domani/Prossima settimana + date input + clear, description in place, subtasks with an add input, facts (assignee, tags, files) only when set; header menu = Tutti i dettagli (TaskDetailModal), Refactor AI (only with aiEnabled), Elimina. Moving a task to another list lives in the modal.
Invariants: lists API returns openTaskCount and doneTaskCount (top-level only); the "N completate" line uses doneTaskCount and the completed rows are fetched only when expanded (parentTaskId=null). No transform or animation on icons; allowed: opacity fades up to 150ms, switch knob, the pulse of .task-loading. Loading buttons stay static (dimmed, disabled), never a spinner.
Traps: shell.css overrides globals.css, so check there first; .task-row > .check-task has margin -12px (detail checks must not); the drawer, rail and sheet on mobile need an opaque background because nested backdrop-filter does not blur; revalidate(except) avoids refetching a deleted task (404); "Prossima settimana" skips a Sunday-to-Monday duplicate of "Domani"; checkbox menu items keep the menu open; e2e rewrites docs/screenshots.
